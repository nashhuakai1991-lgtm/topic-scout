# 内容蒸馏与溯源规范（禁幻觉）

**本文件是硬约束，优先级高于本 skill 其它说明。**

用户要求第 2 条：「综合阅读、梳理并蒸馏这些内容，形成原创文案……
并在文末标注参考了哪些自媒体内容、某句金句的具体出处。」

**关键词是「原创」与「标注出处」——两者同时成立才合格。**

---

## 一、红线：没读到内容，就不准写「它讲了什么」

| 只能拿到 | 只能写 | 不得写 |
| --- | --- | --- |
| 标题 | 「标题为 X，主题涉及 Y」 | 任何内容描述、任何细节 |
| 标题 + 简介 | 「据官方简介，它讲的是 Y」 | 扩写成一段完整论述 |
| 字幕 / 转写 | 「其内容为……」（可作内容总结） | 无 |

> **判定标准**：如果读者问「你凭什么说他讲了 X」，你能指到具体字幕/转写吗？
> 指不到 → 那句话不该存在。

`distill.py` 用 `content_source` 字段落实这条：
`transcript > subtitle > desc > title-only`，
只有 `transcript`/`subtitle` 级才能进「内容总结」位；
`desc`/`title-only` 只能进「主题标注」。

---

## 二、「原创文案」的合规边界

用户明确要「形成**原创**文案」，这意味着：

✅ **允许**：
- 综合多条内容，提炼出**共同结论**（这是再创作）
- 用自己的话重新组织逻辑、补充自己的分析
- 引用短句并标注出处（合理引用）

❌ **禁止**：
- 逐句搬运某一个视频的文案（洗稿）
- 把 X 作者的原创观点包装成自己的原创（不标出处）
- 编造不存在的「金句」并安到某个作者头上

**判定动作**：交付前问自己——「这段文字，如果原作者看到，
我能不能坦然地告诉他『我引用了你的哪一句、出处在这』？」
能 → 合格。不能 → 返工。

---

## 三、金句溯源的硬要求

用户要求「某句金句的具体出处」。`quotes.json` 的规则：

| 字段 | 要求 |
| --- | --- |
| `quote` | 必须是**原文**（标题/简介/字幕里的字符串），不得改写 |
| `quote_type` | 标明来源级别：`transcript`/`subtitle`/`desc` |
| `usable_as_quote` | 只有 `subtitle`/`transcript` 级才为 `true`（可作「他说过」） |
| `url` + `author` + `platform` | 缺一不可，缺了就不算「有出处」 |

**`desc` 级注意**：官方简介是**运营文案**，不一定是作者口播原话。
引用时要写「据其官方简介」，**不能**写「他在视频里说」。

`needs_manual` 列表里的条目（只有标题、无正文）：
**除非拿到字幕/转写，否则不得出现在任何引用位**，
只能在报告里以「待补」形式列出。

---

## 四、覆盖率必须显式声明

交付时必须能一句话说清，例如：

> 「本次共参考 23 条自媒体内容：其中 **8 条有正文级线索**（可作内容总结）、
> **12 条仅有简介**（只做了主题标注）、**3 条仅有标题**（未做内容总结）；
> 另有小红书 / X 两个平台未取到，见数据源状态。」

**不允许**用「我整理了这些内容」的模糊说法掩盖实际覆盖。

---

## 五、教程类内容的额外规范

用户要求「教程类内容需整理出清晰流程，务必图文并茂」。

1. **流程必须步骤化**：用有序列表，每步一句可执行的指令
2. **每步都要能溯源**：标注该步骤来自哪条参考内容 `[平台#rank]`
3. **图文并茂**：
   - 配图优先用**视频截帧**（用户选定），图注**必须**标注来源
   - 截帧语法：`[[fig:frames/xx/f02.jpg|图注|原视频链接]]`
   - 关键步骤至少 1 张图；纯文字步骤要说明为何无图
4. **分歧要暴露**：如果不同作者的步骤/参数不一致，**列出差异**，
   而不是挑一个当成唯一正确做法

---

## 六、交付前自检（逐条打勾）

```
[ ] 每一条「内容总结」背后，我是否真的读过它的正文（字幕/转写）？
[ ] 有没有把「标题+简介」当成「内容总结」写？
[ ] 原创文案是「综合再表达」，还是「逐句搬运」？
[ ] 每句引用是否都能指到具体出处（平台+作者+链接）？
[ ] 金句是原文，还是我改写过的？
[ ] 「据官方简介」和「他说过」有没有混用？
[ ] 覆盖率是否在报告开头就写清楚了？
[ ] 教程流程的每一步是否都标注了来源？
[ ] 每张配图是否都有图注和来源链接？
[ ] needs_manual 里的条目有没有被我硬编进正文？
[ ] 「未做/未取到」的部分是否明确列出？
```

**任何一项不通过 → 返工，不得交付。**
