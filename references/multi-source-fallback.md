# 多信息源兜底（Multi-Source Fallback）

**为什么有这份文档**：用户要的往往是「**多信息源**」——他要的是**交叉印证**，
不是「某个平台的数据」。但 2026-10 实测下，免登录能直接抓的只有 **B站**，
抖音 / 小红书 / 快手**都要求登录态**（详见 `platforms.md`）。

**所以：平台被门禁挡住 ≠ 任务失败。本文件规定「接下来必须做什么」。**

---

## 一、铁律：门禁面前不许躺平，也不许造假

| ❌ 不许 | ✅ 应该 |
| --- | --- |
| 抓不到就只说「抓不到」，然后交一份单源报告完事 | 走下面的兜底阶梯，**主动补足信息源** |
| 把网页资料写成「抖音上有人说」 | 写成「据 <来源> 记载」，并标明是**第三方网页源** |
| 用别的平台数据冒充目标平台 | 如实标注「该平台需登录，未纳入」 |
| 反复重试登录接口、尝试绕过签名 | 停手，转兜底；签名绕过既违规也易失效 |

---

## 二、兜底阶梯（按顺序执行）

### ① 如实告知 + 给选择（必做，第一步）

用 `AskUserQuestion` 一次说清：

> 「抖音/快手/小红书现在都要求登录才能搜。**三个选择**：
> A) 我直接用联网检索补信息源（免登录，快）；
> B) 你扫码登录（数据最全，需手机在手）；
> C) 只要 B站 结果。」

**不要**不声不响就按默认走完——用户有权知道数据边界。

### ② 联网检索补源（推荐，免登录，本节重点）

平台视频抓不到，但**同一主题的公开资料在网页上大量存在**。
用 `WebSearch` 按下面四类靶子检索，构建**独立第三方源**：

| 靶子 | 检索式示例 | 用途 |
| --- | --- | --- |
| **官方文档 / 规范** | `<主题> official docs`、`<主题> 官方文档` | 最高可信度，用来**核校**自媒体说法 |
| **权威媒体 / 厂商博客** | `<主题> 原理`、`<主题> engineering blog` | 事件、时间线、术语核校 |
| **中文整理** | `<主题> 是什么`、`<主题> 入门 教程 整理` | 补足中文语境与术语 |
| **争议 / 反证** | `<主题> 争议`、`<主题> 辟谣`、`<主题> 问题` | 主动找反面证据（见 `verification.md`）|

**实测有效案例**：主题「skill 介绍」→ 通过 WebSearch 拿到
Anthropic 官方博客、agentskills.io 规范、Claude 平台文档、Microsoft 文档、
NVIDIA 释义等 **6 个官方/厂商一手源** + 3 个技术媒体源，
成功用来核校 B站视频里的说法（三级渐进式披露、name/description 必填、
MCP vs Skill 区别等）。

**检索技巧**：
- 中英双语都搜（英文源往往更权威、更早）
- 一次并发多路，不要串行等
- 用**主题里的独特术语**精确匹配（加引号）

### ③ 让用户扫码登录（数据最全）

用户选 B → `--headful` 开**可见窗口**，让用户**直接在窗口里扫**
（⛔ 不要截图二维码发给他，几乎必然过期）。
登录态存 profile，后续复用。

### ④ 换角度检索

同一主题在不同平台有不同叫法，换关键词可能绕开空结果。
例：「skill 介绍」→「Agent Skill」「AI 技能 教程」「Claude Skills」「SKILL.md」。

## 三、⭐ 分层标注（最容易违反的一条）

兜底拿到的网页资料，**必须**与平台条目**分表列出**：

| 层 | 标记 | 写法 | 可信度 |
| --- | --- | --- | --- |
| 平台视频（实测抓到的） | 🔵 | 「`[B站#1]` 的标题是……」 | 高（但仅简介级仍是主题标注） |
| 官方/厂商文档 | 🟢 | 「据 Anthropic 官方文档记载……」 | 高 |
| 技术媒体/博客 | 🟡 | 「据 <站点> 报道……」 | 中 |
| 聚合 Wiki / UGC | ⚪ | 「某 Wiki 称……（未经核实）」 | 中低 |
| 我的推断 | — | 「分析认为……」 | 明确标注 |

**报告里必须有两个分开的表**：
- 「自媒体平台条目」——本次实际检索到的平台内容
- 「第三方网页来源」——兜底检索到的网页/文档，带 URL 与可信度

`make_report.py` 会自动渲染平台条目表；**第三方网页来源表由写作阶段写入正文**
（见下方模板），因为它是 AI 检索所得，不在 `collected.json` 里。

---

## 四、第三方来源表模板（写进正文）

```markdown
### B. 第三方网页来源（多信息源兜底，用于交叉验证）

> ⚠️ 这些不是视频平台条目，而是为「多信息源交叉验证」额外检索的网页/官方文档。
> 引用时写「据 <来源> 记载」，不可表述为「某平台上有人说」。

| # | 来源 | 类型 | 可信度 | 用于印证 |
| --- | --- | --- | --- | --- |
| 1 | [官方文档标题](URL) | 官方一手 | 高 | 定义、机制 |
| 2 | [技术博客标题](URL) | 媒体 | 中 | 生态数据 |
```

---

## 五、交付自检（与主自检合并执行）

```
[ ] 平台被门禁挡住时，是否走了兜底阶梯（而不是直接收工）？
[ ] 是否**主动问过**用户要不要扫码登录？
[ ] 第三方网页来源是否**单独成表**，且带 URL 与可信度？
[ ] 有没有把网页资料写成「某平台有人说」？（这是幻觉，必须改）
[ ] 具体数字（生态规模等）是否标了「据报道」并注明未官方核验？
[ ] 报告「数据源状态」是否如实写明哪些平台未纳入、原因是什么？
```

**任何一项不通过 → 返工。**

---

## 六、一句话原则

> **平台抓不到，就用多源补；补来的源要分层标注；
> 每一句话都要能回答「这是平台的，还是网页的」。**
